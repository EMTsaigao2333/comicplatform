# 技术总结

## 一、技术栈

| 层级 | 技术 | 说明 |
|---|---|---|
| 后端框架 | Spring Boot 2.x | 快速构建 RESTful API |
| ORM | MyBatis-Plus | 简化 CRUD，代码生成器，Lambda 条件构造 |
| 数据库 | MySQL 8.0 | 关系型数据库 |
| 连接池 | Druid | 阿里巴巴数据库连接池 |
| 前端框架 | Vue 3 (Composition API) | 组件化开发 |
| 路由 | Vue Router 4 | 前端路由 + 路由守卫 |
| 状态管理 | Pinia | 用户登录状态、角色判断 |
| HTTP 客户端 | Axios | 前后端通信 |
| 构建工具 | Vite | 开发服务器 + 代理 + 打包 |
| 工具库 | Lombok | 减少样板代码 |

## 二、核心实操记录

### 2.1 项目初始化

1. 用 Maven 创建 Spring Boot 项目，配置 `pom.xml` 引入 MyBatis-Plus、Druid、Lombok 等依赖
2. 配置 `application.properties`：数据库连接、MyBatis-Plus 表前缀 `t_`、驼峰转下划线
3. 创建 Vue 3 项目（Vite），安装 Vue Router、Pinia、Axios

### 2.2 数据库设计

- 用户表 `t_user`：用户名、密码、用户类型（读者/作者/admin）、手机号、邮箱
- 漫画表 `t_comic`：标题、作者、分类、简介、封面、关键词、状态、违规标记
- 章节表 `t_chapter`：所属漫画、章节编号、标题、内容 JSON、发布日期、状态
- 书架表 `t_bookshelf`：用户、漫画、收藏时间
- 数据库视图 `v_bookshelf`：联表查询书架+漫画信息

### 2.3 MyBatis-Plus 代码生成器

- 使用 `FastAutoGenerator` 自动生成 Entity、Mapper、Service、Controller
- 配置要点：作者名、表前缀 `t_`、输出路径
- 生成后手动补全字段映射：数据库字段全小写，需用 `@TableField` 手动映射到驼峰属性名

### 2.4 前后端 API 对接

- 前端 `vite.config.js` 配置代理：`/api` → `http://localhost:8080`
- 后端统一返回 `Result<T>` 封装：`code`、`msg`、`data`
- RESTful 风格：GET 查询、POST 新增、PUT 修改、DELETE 删除
- 统一 `/api` 前缀，方便 Nginx 部署时区分前后端请求

### 2.5 用户认证与权限

- 登录：`POST /api/user/login`，返回用户信息（不含密码）+ `role` 字段
- 注册：`POST /api/user/register`，密码使用 `@JsonProperty(access = WRITE_ONLY)` 确保只进不出
- 前端 Pinia 存储登录状态，计算 `isAdmin`、`isAuthor` 用于菜单显隐
- 路由守卫：`/author/*` 需登录，`/admin` 需管理员

### 2.6 关键业务实现

- **漫画搜索**：分页 + 关键词模糊匹配（标题/作者/关键字）+ 分类筛选
- **书架**：联表查询返回 `BookshelfVO`（含漫画完整信息），支持收藏/取消
- **章节阅读**：`content` 字段存 JSON 图片数组，支持滚动/翻页两种模式
- **漫画发布**：表单验证 + 图片占位 + 编辑模式复用
- **管理员后台**：搜索漫画、标记违规、下架/上架操作
- **作者作品管理**：按作者名查询列表，支持编辑信息和删除

### 2.7 图片策略

- 开发阶段用本地 SVG 占位图（`/public/images/`）
- 封面图通过 text_to_image API 生成并下载到本地
- 统一通过 `src/utils/image.js` 管理图片路径

## 三、踩过的坑

### 3.1 @JsonIgnore 导致注册失败

**现象**：注册时密码写入数据库为 null

**原因**：`@JsonIgnore` 是双向拦截，反序列化（接收请求）时也会忽略字段

**修复**：改为 `@JsonProperty(access = JsonProperty.Access.WRITE_ONLY)`，只限制输出不限制输入

### 3.2 前后端字段名大小写不一致

**现象**：加入书架时报"操作失败"，后端收到 `userid=null, comicid=null`

**原因**：前端发送 `{ userId: 1, comicId: 1 }`，但后端 `Bookshelf` 实体字段是 `userid`、`comicid`，Jackson 默认大小写敏感

**修复**：前端发送时用全小写字段名，与数据库字段保持一致

### 3.3 PUT 接口路径变量缺失

**现象**：修改漫画/章节时 405 错误

**原因**：后端 `@PutMapping` 没有 `/{id}`，前端 `PUT /api/comic/123` 匹配不到

**修复**：改为 `@PutMapping("/{id}")`，用 `@PathVariable` 接收路径中的 id

### 3.4 @RequestMapping 缺少前导斜杠

**现象**：`@RequestMapping("api/comic")` 能跑但不规范

**修复**：改为 `@RequestMapping("/api/comic")`

### 3.5 新增实体未设时间字段

**现象**：新增漫画 `createtime` 为 NULL

**修复**：在 Service 的 `addComic()` 方法中 `comic.setCreatetime(LocalDateTime.now())`

### 3.6 前端 mock 数据掩盖真实问题

**现象**：后端通了但前端仍显示 mock

**原因**：`if (list.length > 0) { ... } else { useMockData() }` 逻辑让后端返回空数组时也走 mock

**修复**：只在请求异常时走 mock，空数据就显示空

### 3.7 下架漫画仍显示在首页

**现象**：管理员下架漫画后首页仍展示

**原因**：分页查询 `listComicsWithPage` 没有过滤掉 `status='已下架'`

**修复**：添加 `wrapper.ne(Comic::getStatus, "已下架")`

### 3.8 VO 的必要性

**教训**：前端需要的数据往往来自多张表，不能直接返回 Entity，需要定义 VO（View Object）组装数据。例如书架页需要漫画标题+封面，但 `Bookshelf` 实体只有外键 ID。

### 3.9 数据库视图 vs 代码组装

- **数据库视图**：SQL 写一次到处复用，适合简单联表
- **代码组装**：灵活可调试，适合需要业务逻辑处理的场景
- 本项目选择代码组装 VO，因为更清晰、可维护

### 3.10 章节内容存储方式变更

**原方案**：独立 `t_chaptercontent` 表存图片

**优化后**：直接在 `t_chapter` 加 `content TEXT` 字段存 JSON 数组，一次查询拿到所有图片

## 四、项目文件结构

```
comicplatform_springbootweb/
├── src/main/java/com/example/comicplatform_springbootweb/
│   ├── common/          # 通用类（Result 统一返回）
│   ├── controller/      # 控制器（API 接口）
│   ├── entity/          # 数据库实体
│   ├── mapper/          # MyBatis 映射器
│   ├── service/         # 业务接口 + 实现
│   └── vo/              # 视图对象
├── comicplatform_vue/comicplatform/
│   └── src/
│       ├── router/      # 路由配置
│       ├── stores/      # Pinia 状态管理
│       ├── utils/       # 工具函数（图片等）
│       └── views/       # 页面组件（Home/Category/Login/...）
└── sundry/              # SQL 脚本等辅助文件
```
